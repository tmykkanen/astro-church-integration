# 03: Theme styles and a client script reach the built Site

**Spec:** `.scratch/package-skeleton/spec.md` · **PRD:** FR-6, NFR-3 · **ADRs:** 0005
**Blocked by:** 02
**Status:** resolved

## Behaviour
The Theme's stylesheet declares `@source` for its own files, so Tailwind generates classes used only inside the Theme, even when the Theme sits in `node_modules`. Tailwind classes in the Site's content are picked up by Tailwind's automatic detection, with no Theme configuration. A client `<script>` on the route ships too.

## Acceptance criteria
- [x] The skeleton route uses a Tailwind class that appears only in Theme files, and the Theme stylesheet declares `@source` for them.
- [x] The Starter Site has one content file using a Tailwind class that appears nowhere else.
- [x] Both classes are in the packed install's built CSS.
- [x] The route's client `<script>` is in the packed install's build output.
- [x] If automatic detection misses Site content, the fallback (an absolute `@source` generated by the integration) is recorded in Comments and the spec. *Not needed: detection found Site content (see Comments).*

## Comments

**2026-11-03: smoke checks added to the harness** (`packages/astro-church/tests/packed/harness.mjs`).

- **What they read:** only what the `/theme-skeleton` page loads: its linked stylesheets and scripts from `dist/`, plus any `<style>` or `<script>` Astro inlined. The Starter Site's own stylesheet (`playground/src/styles/global.css`) isn't loaded by the route, so it can't satisfy them.
- **Literals:** `decoration-wavy` (Theme only, in `theme-skeleton.astro`), `decoration-dotted` (Site content only, in `playground/src/content/test.md`) and the script marker `astro-church:skeleton-script` (a `console.log` argument in the route's `<script>`). A class check matches the class's own selector, not a longer class it prefixes. The marker must be a string the script uses, because minifiers drop unused strings and comments.
- **Decision (Tyler, 2026-11-03):** the content-only class must reach the Theme route's CSS, not just any built CSS. Anywhere in the build would pass from the Site's own stylesheet and wouldn't show that the Theme's Tailwind detects Site content.
- **`@source` path:** relative to the stylesheet. The first attempt, `@source "src/"` in `src/styles/global.css`, resolved to `src/styles/src/`, which doesn't exist; Tailwind doesn't report a missing source, so the Theme-only class silently wasn't generated. Now `@source "../../src"`.
- **Biome:** `css.parser.tailwindDirectives: true` in `biome.json`, so Biome parses `@source`.

**2026-11-03: automatic detection covers Site content; the fallback isn't needed.** In the packed install, with the Theme in `node_modules` and its stylesheet declaring `@source` only for its own `src/`, the Theme route's CSS has a rule for `decoration-dotted`, which appears only in the Site's `src/content/test.md`. Tailwind's automatic detection runs from the Site's project root, not the stylesheet's directory, so the integration doesn't generate an absolute `@source`.

**2026-11-03: review** (standards and spec axes, plus public contract, security and footprint, tests).

- **Public contract:** no change. The stylesheet isn't exported, and `/theme-skeleton` was injected in ticket 01; ticket 08 makes sure it's removed before the first release.

- **Detection base checked:** a reviewer suggested automatic detection is based on the working directory. `@tailwindcss/vite` (4.3.3) passes Vite's resolved `config.root` as the base, which is Astro's `root`, so the spec's "from the project root" stands. Finding dropped.
- **Fixed (agent, test code, approved by Tyler):** the harness header now lists ticket 03's checks. One `readBuilt(url, tag)` helper replaces the duplicated file reading in the CSS and script collection, and the page's HTML is read once, so no helper takes a page parameter it doesn't use. - **Fixed (agent, docs):** the spec's Test seams line now says the route's CSS; Changeset marked not needed; the `test.md` note above.

A page loading both would download those base styles twice. Spec 3.2 should decide that one stylesheet owns `@import "tailwindcss"`. Added to `docs/next-steps.md` under 3.2.
