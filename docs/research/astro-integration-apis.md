# Research: current Astro integration APIs (as of 2026-10-30)

Primary source: https://docs.astro.build/en/reference/integrations-reference/ unless noted. "Unverified" marks claims not confirmed in the docs.

## Versions
- **Latest stable:** `astro@7.4.4`. Astro 7 went stable on 2026-06-22; Astro 6 around 2026-03-10.
- **v7 changes** ([upgrade guide](https://docs.astro.build/en/guides/upgrade-to/v7/)):
  - Vite 8.
  - The Rust compiler gives stricter HTML: unclosed tags error, no nesting auto-fix.
  - `src/fetch.ts` is reserved.
  - `compressHTML: 'jsx'` is the default.
  - Sätteri is the default markdown processor; remark/rehype need `@astrojs/markdown-remark`.
  - `@astrojs/db` is removed.
- **v6 changes** ([upgrade guide](https://docs.astro.build/en/guides/upgrade-to/v6/)):
  - Node 22.12+ and the Vite Environment API.
  - Zod 4 from `astro/zod`.
  - Legacy collections and `Astro.glob()` removed.
  - `prerenderConflictBehavior` is stable.

## Hooks relevant to a theme framework
- **`astro:config:setup`:**
  - `updateConfig` (deep-merged)
  - `injectRoute({pattern, entrypoint: string|URL, prerender?})`
  - `injectScript` (`page-ssr` is used for global CSS)
  - `addMiddleware({entrypoint, order})`
  - `addWatchFile`
  - `createCodegenDir`
  - `addDevToolbarApp`
  - `command`, `isRestart`, `logger`
- **`astro:route:setup`:** can set `prerender` per route.
- **`astro:routes:resolved`:** every route with `origin: 'internal'|'external'|'project'`. This is where collisions between theme and project routes can be detected.
- **`astro:config:done`:** `injectTypes({filename, content})` writes to `.astro/integrations/<name>/` and is auto-referenced. Also provides `buildOutput: 'static'|'server'`.
- **`astro:server:setup`:** `server`, `refreshContent`.
- **Presets:** an integration may return an array of integrations.

## Routing
- [Priority rules](https://docs.astro.build/en/guides/routing/) do not separately rank injected routes against `src/pages`. Same-pattern collisions follow `prerenderConflictBehavior` (default `warn`, highest-priority route wins).
- **Implication:** a consumer can't reliably override a theme route by adding a file; it needs config-level disable/remap or detection in `routes:resolved`.

## Types
- `injectTypes` plus `declare module 'virtual:...'` is the standard way to type virtual modules. It is regenerated by `astro sync`/`dev`/`build`/`check`.
- There is no official guidance on validating integration options; convention is Zod from `astro/zod`.

## Packaging ([publish to npm](https://docs.astro.build/en/reference/publish-to-npm/))
- `.astro`/`.ts`/`.css` may be published raw.
- Use `type: module`, `exports` and `files`.
- Keywords `astro-integration` and `withastro` are needed for `astro add` and the integrations library.
- The integration must be a default-exported function.
- `astro add` passing options is undocumented (unverified).
- Astro auto-handles `ssr.noExternal`/`optimizeDeps` for packages that peer-depend on `astro` or use the `astro-*` naming. This comes from Astro source (`create-vite.ts`), not the docs.

## Content layer
- **No integration API exists to inject collections** ([loader reference](https://docs.astro.build/en/reference/content-loader-reference/)).
- Prior art (Starlight): ship a loader and a schema, and the user wires them in `src/content.config.ts`.

## Prior art: Starlight
- **Routes:** injects a catch-all route and 404 route, with different entrypoints for static vs SSR.
- **Middleware:** sets `Astro.locals.starlightRoute`.
- **Overrides:** `components: { Name: './path.astro' }`, one virtual module per component; a wrapper imports the original from a package export.
- **CSS:** `customCss`, CSS variables, and built-in styles in `@layer starlight`, so unlayered user CSS wins.
- **Plugins:** `config:setup` hooks with `updateConfig`, `addIntegration` and `addRouteMiddleware`.
- **Packaging:** ships compiled TS plus raw `.astro`; peer `astro ^7.2`.

## Other prior art
- **astro-integration-kit 0.20.0:** peer `astro <=6`, experimental. Not a safe foundation for Astro 7.

## Gotchas
- Vite doesn't watch `node_modules` (symlinked workspace packages are fine).
- Tailwind v4 needs `@source` for theme files in `node_modules`.
- Vite-internal plugins must be retested on Vite 8.
- Unverified: whether integrations can set `env.schema` through `updateConfig`. Setting `fonts` that way works: run on Astro 7.3.5 on 2026-11-09 (spec 3.2, ticket 02). See `integration-capabilities.md`.
